## 1. Краткое описание и цель проекта

**Moonbase** — научно-образовательная стратегическая симуляция выживания лунной исследовательской базы на 20 дней, созданная командой **Qcold** в рамках **NASA Space Apps Hackathon 2026**.

### Основная задача игрока
Управлять базой в районе посадки на Луне:
- Обеспечить жизнедеятельность 4 астронавтов (кислород, вода, еда, энергия, здоровье).
- Строить модули базы силами свободных астронавтов на изометрической карте Луны, нарисованной поверх фоновой картинки.
- Выполнять динамические задания от членов экипажа для поддержания их боевого духа (морали).
- Справляться с авариями (поломка системы жизнеобеспечения) и болезнями строителей.
- Пережить **реальную солнечную вспышку NASA DONKI** на 9-й день (построив радиационное укрытие `shelter`).
- Пережить затяжную **лунную ночь** (начинается с 14-го дня), запасшись энергией в батареях.
- Получить подробный разбор миссии (Debrief) с реальными научными данными NASA OSDR, RadLab и CSA.

Игра поддерживает как **одиночный режим** (с автосохранением в `localStorage`), так и **кооперативный мультиплеер** в реальном времени через встроенный легковесный SSE-сервер.

## 2. Стек технологий и инструменты

- **Frontend:** React 19 (`^19.3.1`), TypeScript (`~7.0.2`), Vite (`^8.3.6`).
- **Стилизация:** Чистый CSS с CSS Variables / Tokens (`src/styles/tokens.css`), без громоздких фреймворков.
- **Линтинг:** Oxlint (`^1.90.0`) — сверхбыстрый линтер на Rust. Запуск: `npm run lint`.
- **Backend / Мультиплеер:** Node.js HTTP + Server-Sent Events (SSE). Полностью на стандартной библиотеке Node.js (`node:http`, `node:crypto`), ноль внешних зависимостей. Запуск: `npm run server`.
- **Сборка:** `tsc -b && vite build` (output: `dist/`).
- **Проверки:**
  - `node scripts/run-checks.mjs` — 62 автономных теста баланса и механики движка через Vite SSR без браузера.
  - `node scripts/run-online-checks.mjs` — интеграционные тесты комнаты мультиплеера.
  - `npm run check` — запускает оба набора тестов.

## 3. Архитектурная концепция и ключевые принципы

1. **Детерминированный Headless-движок (`src/engine/`):**
   - Вся логика игры выражена чистой функцией редюсера: `reduce(state: GameState, action: Action): GameState`.
   - В игре **нет скрытого или плавающего недетерминированного рандома**. Случайности (вероятность болезни строителя, выбор вспышки NASA) берутся из `state.seed` с помощью генератора `mulberry32` (`nextRandom(seed)`).
   - Благодаря этому любая игра воспроизводима на 100%. Мультиплеер не требует передачи полного состояния по сети: сервер хранит только `seed` комнаты и последовательность действий (`actions`), рассылая их клиентам.
2. **Единое игровое время:**
   - Время принадлежит движку, а не UI. Действие `{ type: "tick", ms: number }` двигает внутренние часы `clockMs`, таймеры строительства и дни.
   - Игровой день длится **120 000 мс (2 минуты)**. Стройка любого модуля — **60 000 мс (1 минута = полдня)**.
3. **Разделение слоёв:**
   - `src/data/` — JSON-файлы с параметрами модулей, событий, подсказок NASA.
   - `src/engine/` — чистая бизнес-логика (не зависит от React и DOM).
   - `src/ui/` — компоненты React (отрисовка карты, HUD, модальных окон).
   - `src/net/` — клиентский сетевой слой для работы с комнатами.
   - `src/i18n/` — строгая типизированная мультиязычность (UK, EN, RU).

## 5. Модели данных и система типов (`src/types.ts`)

### Ресурсы (`Resources`)
```typescript
export type ResourceKey = "oxygen" | "water" | "food" | "energy" | "health" | "materials";
export type Resources = Record<ResourceKey, number>;
```
- **oxygen (Кислород):** 0..100%. Жизненно важный.
- **water (Вода):** литры. Жизненно важный. Базовый лимит 100, расширяется Складом (`storage`).
- **food (Еда):** кг. Жизненно важный. Базовый лимит 100, расширяется Складом.
- **energy (Энергия):** кВт·ч. Нужна для работы модулей. Базовый лимит 100, расширяется Батареями (`battery`).
- **health (Здоровье экипажа):** 0..100%. При падении до 0 миссия проиграна (`lost`).
- **materials (Материалы/реголит):** кг. Нужны для постройки укрытия и складов. Базовый лимит 100.

### Модули (`ModuleType`, `ModuleDef`, `PlacedModule`)
```typescript
export type ModuleType =
  | "habitat"      // Жилой модуль: дает базовый уют, требует энергию
  | "lifeSupport"  // Жизнеобеспечение: производит O2 и рециркулирует воду
  | "solar"        // Солнечные панели: дают энергию днем (ночью 0)
  | "battery"      // Батарея: копит энергию (+50 к емкости), отдает ночью (+6/день)
  | "greenhouse"   // Теплица: производит еду и O2, потребляет воду и энергию
  | "shelter"      // Радиационное укрытие: защищает от солнечной вспышки
  | "iceMine"      // Добыча льда: добывает воду (ставится только на лед 'ice')
  | "rockMine"     // Карьер реголита: добывает материалы (только на камни 'rock')
  | "storage"      // Склад: +100 к лимиту воды, еды и материалов
  | "medbay";      // Медпункт: ускоряет и удешевляет лечение болезней

export type ModuleDef = {
  type: ModuleType;
  cost: Partial<Resources>;         // Цена постройки
  perDay: Partial<Resources>;       // Дневная дельта
  nightPerDay?: Partial<Resources>; // Дельта ночью (если отличается)
  capacity?: Partial<Resources>;    // Добавочная вместимость склада
  builder?: Role;                   // Приоритетная роль строителя
};

export type PlacedModule = {
  slot: number;                     // row * MAP_COLS + col
  type: ModuleType;
  broken: boolean;                  // Спец-статус: поломан (lifeSupport в аварии)
  build?: {                         // Если модуль в процессе постройки
    leftMs: number;                 // Сколько мс осталось строить (всего BUILD_MS = 60000)
    totalMs: number;
    crewId: number | null;          // Кто строит (null, если строитель заболел)
    sickAt?: number;                // Порог leftMs, на котором строитель заболеет (по seed)
  };
};
```

### Экипаж (`Role`, `CrewMember`)
```typescript
export type Role = "engineer" | "scientist" | "technician";

export type CrewMember = {
  id: number;                       // 1: Алиса (инженер), 2: Максим (учёный), 3: Виталий (врач), 4: Даниил (техник)
```

```typescript
export type GameState = {
  seed: number;                     // Детерминированный генератор псевдослучайных чисел
  illness: { crewId: number; slot: number } | null; // Текущая активная болезнь
  sickCount: number;                // Количество болезней за миссию (макс 3)
  lastIllnessDay: number;           // День последней болезни (пауза не менее 5 дней)
  tasks: Task[];                    // Список всех выданных заданий
  crew: CrewMember[];               // 4 члена экипажа
  clockMs: number;                  // Прошло мс в текущем дне (0..120000)
  history: HistoryEntry[];          // Лог фактов для итогового разбора
  flare: Flare | null;              // Выбранная для миссии вспышка из NASA DONKI
  day: number;                      // Текущий день (1..20)
  isNight: boolean;                 // true, если day >= 14
  resources: Resources;             // Текущие значения 6 ресурсов
  modules: PlacedModule[];          // Размещенные модули на карте
  pending: { inDays: number; key: ResourceKey; amount: number; reason: string }[]; // Отложенный урон
  activeEvent: string | null;       // "breakdown" | "flare" | "illness" | null
  log: { day: number; text: string }[]; // Текстовый бортовой журнал
  status: "playing" | "won" | "lost";
};
```

### Действия редюсера (`Action`)
```typescript
export type Action =
  | { type: "tick"; ms: number }                        // Прогресс игрового времени
  | { type: "nextDay" }                                 // Промотка остатка дня
  | { type: "build"; slot: number; module: ModuleType } // Начать постройку в слоте
  | { type: "repair"; slot: number }                    // Починить поломанный модуль (кликом по нему)
  | { type: "research"; id: "moonDust"; answer: "shield" | "brush" } // Ответ в научной экспедиции (один раз за миссию)
  | { type: "resolveEvent"; choice: string };           // Сделать выбор в модальном событии
```

## 6. Игровой движок (`src/engine/`)

### 6.1 Время и часы (`constants.ts`, `engine.ts`)
- **`MISSION_DAYS = 20`**: полная длительность лунной миссии.
- **`NIGHT_START = 14`**: с 14 по 20 день наступает 14-суточная лунная ночь.
- **`DAY_MS = 120000`** (2 минуты реального времени).
- **`BUILD_MS = 60000`** (1 минута реального времени = 0.5 игрового дня).
- **Логика тиков:** Функция `tick(state, ms)` разбивает входящее время на кванты до ближайшего из событий:
  1. Окончание текущего дня (`DAY_MS - s.clockMs`).
  2. Момент наступления болезни строителя (`msUntilSick(s)`).
  3. Оставшийся миллисекундный остаток.
- При наступлении модального окна (`activeEvent !== null`) ход времени автоматически блокируется.

### 6.2 Ресурсы, склады и дефициты
- **Базовый лимит хранения:** `BASE_CAPACITY = 100`.
- **Емкость базы (`capacityOf`):**
  - Вода, Еда, Материалы: `100 + 100 * (число готовых storage)`.
  - Энергия: `100 + 50 * (число готовых battery)`.
  - Кислород и Здоровье: всегда жесткий потолок `100`.
- **Ежедневное потребление экипажем (`CREW_PER_DAY`):**
  - Кислород: `-5` в день.
  - Вода: `-3` в день.
  - Еда: `-4` в день.
- **Блэкаут (нет энергии):**
  - Если `energy <= 0`, модули-потребители энергии отключаются и не дают полезный выход. Записывается событие `blackout`.
- **Критический дефицит жизненных ресурсов (`VITAL`):**
  - Если кислород, вода или еда падают до нуля, в `pending` кладется отложенный урон: через 2 дня (`inDays: 2`) наносится `-25` к здоровью (`SHORTAGE_DAMAGE = 25`). Дефицит повторяется каждые 2 дня, пока ресурс не восполнен.

### 6.3 Экипаж и строители (`crew.ts`, `crewData.ts`)
В игре 4 астронавта (названия роли в коде: `engineer`, `scientist`, `doctor`, `technician`):
1. **Алиса (Инженер, id: 1):** энергия и склады (`solar`, `battery`, `storage`).
2. **Максим (Учёный, id: 2):** ресурсы и биосфера (`greenhouse`, `iceMine`, `rockMine`).
3. **Виталий (Врач, id: 3):** здоровье и защита (`shelter`, `medbay`).
4. **Даниил (Техник, id: 4):** системы базы и жильё (`habitat`, `lifeSupport`).

**Правило выбора строителя (`pickBuilder`):**
- Ищется свободный астронавт (`status.kind === "free"`), чья роль совпадает с полем `builder` в `modules.json`.
- Если профильный специалист занят, назначается любой другой свободный астронавт.
- Если свободного экипажа нет (`hasFreeCrew(state) === false`), строительство заблокировано.

### 6.4 Строительство и карта (`placement.ts`)
- Карта нарисована поверх фоновой картинки `assets/moon-bg.webp`. Клетки, кратеры, камни, лёд и посадочная площадка описаны в `src/data/map.ts` (список `FEATURES` в пикселях картинки). Если фон поменяется, поправьте `FEATURES`.
- Сетка карты: 20 рядов × 14 колонок, клетка 150×75 единиц.
- «Шахматная» изометрия с формулой перехода `toDiamond(row, col)`.
- Стартовые модули ставятся функцией `nearestGroundSlot(x, y)` по координатам на картинке.
- **`BUILD_RADIUS = 3`**: строить модуль можно не далее 3 клеток по диагональной метрике от любого уже размещенного модуля базы.
- **Ограничения рельефа:**
  - `iceMine` ставится только на лед (`terrain === "ice"`).
  - `rockMine` ставится только на камни (`terrain === "rock"`).
  - Все остальные модули ставятся только на грунт (`terrain === "ground"`).
  - Посадочная площадка (`landing`) и кратеры (`crater`) непроходимы для застройки.
- **Процесс стройки:**
  - При старте списываются ресурсы по `def.cost`.
  - Модуль добавляется в `state.modules` с объектом `build: { leftMs: 60000, totalMs: 60000, crewId }`.
  - **Пока модуль строится, он НЕ производит ресурсов, НЕ потребляет энергию и НЕ расширяет вместимость складов!**
  - По истечении 60 секунд строитель освобождается, модуль переходит в рабочий режим, и сразу вызывается `reviewTasks`.

### 6.5 Болезни и медпункт
- **Шанс болезни (`ILLNESS_CHANCE = 0.4`):** проверяется при старте стройки детерминированно по `state.seed`.
- Условия возможности болезни:
  - День миссии >= 2.
  - Всего болезней за миссию < 3 (`MAX_ILLNESS = 3`).
  - Прошло не менее 5 дней с прошлой болезни (`ILLNESS_GAP = 5`).
  - Нет активной болезни и других строек с запланированной болезнью.
- Если кубик выпал: строитель заболевает в случайный момент стройки (между 30% и 70% готовности). Время останавливается, выскакивает окно болезни.
- **Варианты выбора игрока (`events.json`):**
  - **Вылечить (`treat`):**
    - Без медпункта: стоит `-10 воды` и `-8 еды`.
    - С медпунктом (`medbay`): стоит `-5 воды` и `-4 еды`.
    - Строитель выздоравливает мгновенно и продолжает достраивать свой модуль.
  - **Проигнорировать (`ignore`):**
    - Урон здоровью базы: `-5 здоровья`.
    - Больной переходит в статус `sick` и выбывает на **2 дня** (с медпунктом — на **1 день**).
    - Его стройка замирает (`crewId: null`).
    - Если есть другой свободный член экипажа, он автоматически перехватывает стройку (`assignWaiting`).

### 6.6 Система заданий экипажа (`tasks.ts`)
В игре 16 заданий (`TASK_DEFS`), привязанных к ролям членов экипажа:
- Инженер просит: панели (`solar`, `solar2`, `solar3`), батареи к ночи (`battery`, `battery2`), склад (`storage`).
- Ученый просит: теплицу (`greenhouse`, `greenhouse2`), карьер (`rocks`), ледник (`ice`), накопить материалы (`stockMaterials >= 50`).
- Техник просит: укрытие к вспышке (`shelter`), систему жизнеобеспечения (`air2`), медпункт (`medbay`), воду (`stockWater >= 80`), второй жилой модуль (`habitat2`).

**Правила генерации заданий:**
- До 10-го дня (`TASKS_BUSY_UNTIL`): выдается до 2 заданий в день (`TASKS_BUSY = 2`).
- После 10-го дня: выдается 1 задание в день (`TASKS_CALM = 1`).
- Лимит одновременно открытых заданий: **не более 4** (`MAX_OPEN = 4`).
- Сроки: обычные задания — 5 дней. Убежище — строго до вспышки (9-й день). Батареи — строго до лунной ночи (14-й день).
- **Мораль:**
  - Выполнено в срок: мораль экипажа `+10`.
  - Просрочено: мораль экипажа `-10`.

### 6.7 События и космическая погода NASA (`events.ts`)
1. **День 6 — Поломка (`breakdown`):**
   - Выходит из строя модуль `lifeSupport` (кислород перестает вырабатываться).
   - Выбор: починить немедленно (`repair`, стоит 10 воды и 10 энергии) или игнорировать. Также починить можно кликом по модулю на карте.
2. **День 9 — Солнечная вспышка (`flare`):**
   - Берется реальная вспышка NASA DONKI класса M5+ / X (например, X1.2).
   - Выбор «Укрыться» (`hide`): если есть построенный `shelter`, урона 0. Если укрытия нет — экипаж получает `-10 здоровья`.
   - Выбор «Работать» (`work`): экипаж получает `-30 здоровья`.

### 6.8 Итоговый разбор миссии (`debrief.ts`)
При победе (прожито 20 дней) или поражении (`health <= 0`):
- `collectFacts(state)` собирает 22 логических факта (`won`, `lost`, `builtGreenhouse`, `flareHidInShelter`, `batteryBeforeNight`, `illnessTreated` и др.).
- По правилам из `src/data/debrief.json` формируется отчет:
  - Вердикт и титул («Миссия перервана», «Місію виконано на відмінно!»).
  - Пункты «Что помогло» (`helped`).
  - Пункты «Что помешало» (`hurt`).
  - Пункты «Реальные факты NASA» (`facts`) со ссылками на официальный каталог DONKI.
  - Образовательные карточки-подсказки: `hintId` пункта разбора указывает на запись в `hints.json`, текст берётся из словаря (`hint.<id>`).
  - Один «факт дня» о здоровье астронавтов: `missionFact(state)` выбирает его по seed из `health.json` (текст `fact.<id>`).
  - Итоговый экран рисует `ui/ResultsScreen.tsx` (см. 6.11).

### 6.9 Сохранения и рекорды (`storage.ts`)
- Ключи: `moonbase:save`, `moonbase:records`, `moonbase:lang`.
- **`SAVE_VERSION = 6`**: предотвращает загрузку несовместимых версий состояния. Версия 5 (список `research` ещё не было) мигрирует при загрузке: ей добавляется `research: []`. Всё старше 5 не загружается.
- Автосохранение в `App.tsx` каждые 2000 мс и по событию `beforeunload`.

### 6.10 Научная экспедиция (`research`)
- В боковой панели есть карточки с вопросами. Первая про лунную пыль (id `moonDust`): «электрический экран» верно, «смахнуть щёткой» нет. Вторая разведка льда (id `iceScout`): ответ `ice` даёт +22 воды и +8 энергии, ответ `rock` даёт +5 материалов.
- Действие `{ type: "research", id: "moonDust", answer }` обрабатывает `completeResearch` в `engine.ts`: верный ответ даёт +24 энергии и +12 материалов, неверный +8 энергии. Награда не выходит за лимит хранения.
- Каждое исследование выполняется один раз за миссию и только пока идёт игра. `state.research` хранит и id, и пару `id:ответ` (например, `moonDust`, `moonDust:shield`).
- Действие разрешено на сервере (`ACTION_TYPES`), поэтому работает и в совместной игре.
- Тексты: ключи `research.*` в трёх словарях. Источник: страница NASA про лунный реголит (ссылка в карточке).

### 6.11 Итоговый экран, «Данные NASA» и рекорды
- **`ui/ResultsScreen.tsx`** показывает итог миссии: заголовок и оценку вердикта, итог, дни и здоровье, лучший результат, разделы «Что помешало», «Что помогло», «Данные NASA» (настоящая вспышка со ссылкой), «Как это у NASA» (до двух подсказок) и «Знаете ли вы?» (факт по seed). Вердикт «на отлично» не выдаётся, если экипаж остался без ответа на большинство заданий.
- **`ui/SourcesPanel.tsx`** показывает экран «Данные NASA» из `data/sources.json` (названия и описания в словарях: `source.<id>.name` и `.usedFor`; флаг `inGame` говорит, подключён ли источник). Открывается кнопкой в главном меню и в итогах.
- **Рекорды.** Когда одиночная миссия заканчивается, `App.tsx` один раз вызывает `saveRecord(recordFrom(state))`. Лучшие 10 результатов лежат в `moonbase:records` (победа важнее поражения, потом здоровье, потом дни). В совместной игре рекорды не пишутся.
- Что настоящее, а что нет, описано для жюри в `docs/DATA.md`.

## 7. Данные и интеграции с NASA (`src/data/`, `scripts/`)

- **`src/data/nasa/flares.json`**: массив реальных экстремальных солнечных вспышек NASA DONKI.
  - Поля: `id`, `date`, `peakTime`, `class` (например, "X1.2"), `location`, `activeRegion`, `link`, `source: "NASA DONKI"`.
- **`scripts/fetch-donki.mjs`**: парсер NASA API.
  - Источник 1: прямой эндпоинт CCMC (`https://ccmc.gsfc.nasa.gov/DONKI/WS/get/FLR`).
  - Источник 2 (fallback): `https://api.nasa.gov/DONKI/FLR` с ключом `NASA_API_KEY`.
- **`src/data/health.json` & `hints.json`**: список фактов и подсказок (id и источник). Сами тексты на трёх языках лежат в словарях (`fact.*`, `hint.*`). Темы:
  - Деминерализация костей (~1% в месяц в невесомости).
  - Атрофия мышц и 2-часовые ежедневные тренировки на МКС.
  - Сбои циркадных ритмов и иммунитета (NASA OSDR).
  - Рециркуляция до 98% воды на МКС.
  - Радиационные риски и база дозиметрии RadLab.
  - Космическое растениеводство по исследованиям Канадского космического агентства (CSA).

## 8. Сетевой мультиплеер и сервер (`server/`, `src/net/`)

### Сервер (`server/index.mjs`)
- Запуск: `npm run server` (по умолчанию порт 8787).
- Полностью in-memory: комнаты хранятся в `Map<string, Room>`.
- Спецификация REST / SSE API:
  1. `POST /api/rooms/:name/join`
     - Вход в комнату (имя 1-20 латинских букв).
     - Возвращает: `{ playerId, role, seed, actions, players, hostId }`.
     - Роли распределяются по очереди: сначала отсутствующие из списка `["engineer", "technician", "doctor", "scientist"]` (четыре роли, как четыре члена экипажа).
     - Первый вошедший игрок становится хостом (`hostId`).
  2. `GET /api/rooms/:name/events?player=ID&from=N`
     - Server-Sent Events (SSE).
     - Передает поток действий, начиная с индекса `from`, и обновления списка игроков.
  3. `POST /api/rooms/:name/actions`
     - Прием действия от игрока `{ player, action }`.
     - **Авторизация тиков:** действие `type: "tick"` разрешено присылать **только хосту** (`hostId`). Если пришлет не хост, возвращается HTTP 409 `{ error: "not host" }`.
     - Разрешенные типы действий: `tick`, `build`, `resolveEvent`, `repair`, `research`. При неизвестном типе — HTTP 400.
     - **Правило:** список на сервере (`ACTION_TYPES`) должен совпадать со списком `Action` из `src/types.ts` без `nextDay` (пропускать день онлайн нельзя). Новое действие добавляется в оба места; `scripts/run-online-checks.mjs` проверяет это сам и упадёт, если они разошлись.

### Клиент (`src/net/online.ts`)
- Подключение через `joinRoom(name)` и `openStream(session, from, handlers)`.
- Автоматический реконнект SSE при обрыве связи (таймаут 2 сек) с сохранением индекса последнего примененного действия `applied`.
- Пакетная отправка тиков хостом (`ONLINE_TICK_MS = 500`), чтобы не спамить сеть.

## 9. Процедурный звуковой движок (`src/audio/audio.ts`)

В игре реализован встроенный ретро-футуристичный аудиодвижок на чистом **Web Audio API** без внешних тяжелых звуковых файлов (ноль килобайт внешних ассетов):
- **Синтез в реальном времени:** Осцилляторы (`sine`, `square`, `sawtooth`, `triangle`), биквадратные фильтры (`lowpass`, `bandpass`) и процедурный генератор белого шума.
- **Поддерживаемые звуковые эффекты:**
  1. `playClick()` — короткий тактильный клик при нажатии кнопок интерфейса.
  2. `playTaskToast()` — исторический двухтональный радиосигнал квиндар-тона NASA Apollo (2525 Гц + 2475 Гц) при получении нового задания.
  3. `playBuildStart()` — механический щелчок монтажа и металлический отклик закладки фундамента.
  4. `playBuildComplete()` — восходящий 3-нотный мажорный перезвон (До-Ми-Соль) завершения строительства.
  5. `playRepair()` — звук электрической дуги и трещотки инструмента при починке жизнеобеспечения.
  6. `playAlarm("flare" | "breakdown" | "illness")` — космическая сирена тревоги при вспышке Солнца, частый двойной сигнал при аварии или нисходящий тон болезни.
  7. `playDayChange()` — мягкий восходящий перезвон нового дня.
  8. `playNightfall()` — глубокий низкочастотный рокот наступления лунной ночи (с 14 дня).
  9. `playVictory()` / `playDefeat()` — победное ретро-арпеджио или меланхоличный спадающий минорный аккорд при окончании миссии.
  10. `startAmbient()` / `stopAmbient()` — фоновый низкочастотный гул жилого отсека (55 Гц) с мягким шумом вентиляции станции.
- **Управление звуком:**
  - Кнопка включения/выключения звука (`SoundOnIcon` / `SoundOffIcon`) в шапке HUD (`DayClock`) и главном меню (`MainMenu`).
  - Состояние сохраняется в `localStorage` (`moonbase:muted`).
  - Реактивная подписка на изменения (`subscribe`).
  - Ленивая инициализация `AudioContext` с автоматическим `resume()` по первому клику игрока (в соответствии с политиками автовоспроизведения современных браузеров).
  - Безопасен для headless-среды и SSR (проверка `typeof window !== "undefined"`).

## 11. Локализация i18n (`src/i18n/`)

- Поддерживаемые языки: **Украинский (`uk`)**, **Английский (`en`)**, **Русский (`ru`)**.
- Язык по умолчанию: `uk`.
- Функция интерполяции параметров: `t("key", { param: "value" })`.
- Плюрализация: функция `days(n)` возвращает «1 день», «2 дні», «5 днів» / «1 day», «2 days» с учетом грамматических правил языка.
- **ВАЖНО для разработчиков и ИИ:**
  - Пустых файлов `en.ts`, `ru.ts`, `uk.ts` в корне больше нет (удалены), не создавайте их заново.
  - Настоящие словари лежат в **`src/i18n/uk.ts`**, **`src/i18n/en.ts`**, **`src/i18n/ru.ts`**.
  - Добавляя новый ключ в один словарь, обязательно продублируйте его во все три, иначе TypeScript сообщит об ошибке типов словаря.

## 12. Тестирование и проверка баланса (`checks.ts`, скрипты)

В проекте реализована система тестирования баланса через симуляцию прохождения миссий «игроком-роботом» (`playMission`):
- Запуск тестов: `npm run check` (или `node scripts/run-checks.mjs`).
- **48 строгих тестов проверяют:**
  1. Невозможность победы без построек (база гибнет на 19 день).
  2. Рискованная стратегия гибнет раньше осторожной (на 17 день).
  3. Подготовленная база гарантированно побеждает на 20 день со 100% здоровьем.
  4. Без укрытия вспышка сносит здоровье до 90%.
  5. Без батарей лунная ночь оставляет базу без энергии.
  6. Стройка занимает ровно 60 секунд.
  7. Лимит занятости: когда все 4 астронавта строят, следующий модуль не ставится.
  8. Задания выдаются строго по лимитам (не более 4 открытых).
  9. Детерминированность генерации случайных событий по `seed`.
  10. Медпункт удешевляет лечение ровно в 2 раза и сокращает болезнь до 1 дня.
  11. Склады корректно увеличивают максимальную вместимость до 200 единиц.
  12. Тесты разбора миссии (`debrief`) на отсутствие опечаток и незаполненных скобок шаблонов.
  13. Мультиплеерные тесты комнат (`scripts/run-online-checks.mjs`): четыре роли, права ведущего, валидация действий и совпадение списка действий движка и сервера.
  14. Починка: цена берётся из `events.json`, при открытом окне поломки закрывает его, после конца игры не работает. Разбор различает «починили сразу», «починили позже» и «не починили».
  15. Научная экспедиция: награда, один раз, лимит хранения, не работает после конца игры.

## 13. Инструкции по модификации (Playbook для ИИ)

Если перед вами стоит задача доработать проект, следуйте этим пошаговым рецептам:

### Рецепт 1: Добавление нового модуля
1. Добавьте тип модуля в объединение `ModuleType` в `src/types.ts`.
2. Опишите параметры модуля в `src/data/modules.json`:
   ```json
   {
     "type": "newModule",
     "cost": { "energy": 10, "materials": 15 },
     "perDay": { "water": 2, "energy": -3 },
     "nightPerDay": { "energy": -1 }, // опционально
     "capacity": { "water": 50 },      // опционально
     "builder": "technician"           // engineer | scientist | technician
   }
   ```
3. Добавьте переводы в `src/i18n/{uk,en,ru}.ts`:
   - `module.newModule.name`: название.
   - `module.newModule.desc`: описание.
4. Добавьте SVG-отрисовку модуля в `src/ui/map/art.tsx`:
   - Добавьте константу высоты в `ART_HEIGHT`.
   - Добавьте компонент `<NewModuleArt />` в `ModuleArt` и `ModulePreview`.
5. Запустите `npm run check && npm run build` для подтверждения целостности.

### Рецепт 2: Добавление нового задания экипажа
1. Откройте `src/engine/tasks.ts`.
2. Добавьте объект задания в массив `TASK_DEFS`:
   ```typescript
   {
     id: "myTask",
     role: "engineer", // кто просит: engineer | scientist | technician
     fromDay: 5,       // не выдавать ранее 5 дня (опционально)
     deadline: () => 12, // жесткий дедлайн (опционально, иначе state.day + 5)
     done: (s) => s.resources.materials >= 70 // условие выполнения
   }
   ```
3. Добавьте переводы в `src/i18n/{uk,en,ru}.ts`:
   - `task.myTask`: краткое название задания.
   - `task.myTask.why`: почему экипаж об этом просит.
4. Запустите `node scripts/run-checks.mjs`.

### Рецепт 3: Добавление нового случайного или сюжетного события
1. Опишите структуру события в `src/data/events.json`:
   ```json
   {
     "id": "meteorShower",
     "choices": [
       { "id": "shield", "cost": { "energy": 20 }, "result": "log.meteorShield" },
       { "id": "endure", "cost": { "health": 15 }, "result": "log.meteorHit" }
     ]
   }
   ```
2. В `src/engine/events.ts` добавьте день вызова события в `SCHEDULE` или логику в `eventForDay(day)`.
3. Добавьте языковые ключи в `src/i18n/{uk,en,ru}.ts`:
   - `ev.meteorShower.title`
   - `ev.meteorShower.text`
   - `ev.meteorShower.shield.label` / `.hint`
   - `ev.meteorShower.endure.label` / `.hint`
   - `log.meteorShield` / `log.meteorHit`
4. Если событие влияет на итог, зарегистрируйте факт в `FACT_NAMES` (`src/engine/debrief.ts`) и правило в `src/data/debrief.json`.

## 14. Известные особенности, подводные камни и история решений

1. **Экипаж из 4 человек (состав менялся, помните историю):**
   - Сначала был экипаж из 4 с врачом Софией (id 3), потом Софию убрали (экипаж из 3, роль врача пропала), затем врач вернулся под именем Виталий (id 3).
   - Сейчас: Алиса (инженер, id 1), Максим (учёный, id 2), Виталий (врач, id 3), Даниил (техник, id 4). Имена в словарях `crew.n<id>`, в украинском и английском другие написания.
   - Убежище и медпункт закреплены за врачом (`builder: "doctor"` в `modules.json`). Задания про них просит врач.
   - Каждый раз, когда состав меняется, меняйте вместе `engine.ts` (`CREW_ROLES`), `crewData.ts`, словари, `modules.json`, `tasks.ts`, серверные роли и `SAVE_VERSION`.
2. **Лишние файлы убраны:**
   - Пустые `en.ts`, `ru.ts`, `uk.ts` в корне, пустой `src/tokens.css` и закоммиченная папка `dist/` удалены из репозитория. `dist/` собирается заново (`npm run build`, деплой на Pages делает это сам). Все переводы живут в `src/i18n/`.
3. **Отсутствие паузы и ускорения в UI:**
   - Решением команды в игре нет кнопок паузы или ×2 скорости. День течет непрерывно со скоростью ровно 2 минуты (`DAY_MS = 120000`). Таймер замирает только при открытии модального окна события или окна правил.
4. **Строительство не блокирует интерфейс, но блокирует человека:**
   - Строит конкретный астронавт. Игрок видит в панели экипажа, кто именно строит здание. Когда все астронавты заняты, меню блокирует закладку новых строек.
5. **Детерминизм `seed`:**
   - Всегда передавайте и обновляйте `seed` при вызове `nextRandom`. Никогда не используйте `Math.random()` внутри редюсера `reduce`, чтобы не сломать мультиплеерную синхронизацию и прохождение автоматических проверок.
