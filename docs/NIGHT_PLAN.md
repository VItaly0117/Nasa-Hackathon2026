### Фаза 2. Косметика и анимации на 60 кадров
Делается **после A3 и A4**: плавность зависит от того, что часы не перерисовывают весь экран.

**Правила анимаций:**
- Только `transform` и `opacity`. Никаких анимаций `width`, `height`, `top`, `left`, `box-shadow` на больших областях.
- Анимации на CSS (transitions, keyframes) или Web Animations API, **а не** покадровым `setState`.
- Состояние игры обновляется 10 раз в секунду, поэтому между тиками плавность даёт CSS: прогресс-кольца и полоски идут через `transition: transform 100ms linear`, счётчики через CSS-переменные.
- `will-change` только на немногих долгоживущих элементах.
- Обязательно уважать `prefers-reduced-motion`: при нём анимации заменяются мгновенными переходами.
- Не ломать звук и не добавлять тяжёлые частицы на всю карту.

**Список работ** (трудоёмкость от малой к большой, делать по порядку):
1. Стартовая расстановка астронавтов (сейчас кучей, подписи накладываются) и аккуратные подписи.
2. Нажатия и наведение кнопок: отклик, фокус для клавиатуры.
3. Плавные счётчики и вспышки на плашках ресурсов при изменении.
4. Пульсация и искры при завершении стройки, плавное кольцо прогресса.
5. Появление и исчезновение окон событий, карточек заданий, баннера дня.
6. Плавный переход день ↔ ночь (через CSS-переменные, без пересчёта в React).
7. Итоговый экран: поэтапное появление блоков, взлёт ракеты при победе.
8. Подгонка плашек ресурсов и меню строительства под узкие экраны.

## 60 кадров: как проверяем

Замер в браузере на 60 секундах игры: счётчик кадров через `requestAnimationFrame` и долгие задачи через `PerformanceObserver`.

| Показатель | Порог |
|---|---|
| Средний FPS | не ниже 55 |
| Кадров дольше 33 мс | не больше 3% |
| Долгих задач (больше 50 мс) после загрузки | 0 |
| Перерисовок `Game` из-за часов | 0 (часы перерисовывают только себя) |

Замер сравнивается с базовой линией из фазы 0. Если стало хуже, анимация откатывается. Codex делает `npm run perf` в Playwright; пока его нет, меряю сам.
