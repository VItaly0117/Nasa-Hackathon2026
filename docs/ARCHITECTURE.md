# Архитектура Moonbase

Документ описывает, из каких слоёв состоит проект, кто кого может импортировать и как идут данные. Правила слоёв проверяет `npm run architecture`, поэтому нарушение роняет CI.

## Слои

```
content  ←  engine  ←  session  ←  features  ←  app
 данные      чистое      хранилище,    экраны и     порядок
 и карта     ядро        сети,         панели       экранов
                         сохранения
i18n, audio, ui — вспомогательные: ими пользуются features и app, ядро ими не пользуется
```

| Слой | Папка | Что внутри | Что нельзя |
|---|---|---|---|
| Данные | `src/content/` | JSON с модулями, событиями, подсказками и источниками, `map.ts`, вспышки DONKI | логика |
| Ядро | `src/engine/` | `reduce(state, action)`, системы (день, экипаж, задания, события, болезнь), стройка, разбор миссии | React, DOM, `localStorage`, `i18n`, `Math.random`, `Date.now`, звук, сеть, сессия |
| Сессия | `src/session/` | хранилище, одиночная и совместная игра, сохранения и рекорды, React-подписки | компоненты, звук, `features` |
| Экраны | `src/features/` | `game/` (HUD, карта, события), `menu/`, `story/`, `results/` | |
| Общее | `src/ui/` | примитивы без знания об игре: иконки, свёртывание панелей, `ErrorBoundary`, подсказка «поверни телефон» | |
| Тексты | `src/i18n/` | словари ru, uk, en, типизированный `t(MessageKey)`, `formatMsg` для журнала | |
| Звук | `src/audio/` | процедурный звук на Web Audio: `audio.ts` (общий выход, мьютинг, публичный `sound`), `effects.ts` (одиночные звуки), `chain.ts` (общий выход: громкость, срез верха, компрессор), `noise.ts` | |
| Сеть | `src/net/` | клиент комнат (SSE) | |
| Приложение | `src/App.tsx`, `src/main.tsx` | последовательность экранов: меню → пролог → правила → игра | |

Снаружи ядро импортируется **только** через `@/engine` (файл `engine/index.ts`), глубоких импортов нет. Для путей используется алиас `@/` (то есть `src/`).

## Ядро

- Одна чистая функция `reduce(state, action)`. Действия: `tick`, `build`, `repair`, `research`, `resolveEvent` (и внутреннее `nextDay`). Время двигает действие `tick`; игровой день 120 с, стройка 60 с.
- Вся случайность идёт от `state.seed` (`mulberry32`). Поэтому игра воспроизводима: сервер хранит только seed комнаты и порядок действий.
- В состоянии нет текста. Журнал и причины отложенных эффектов хранят `{ key, params }` (`Msg`), перевод делает `i18n/messages.ts` при показе. Смена языка меняет весь журнал сразу, а состояние от языка не зависит (проверка в `checks.ts`).
- Разбор миссии делится на `engine/debrief.ts` (факты и вердикты, язык не нужен) и `features/results/report.ts` (тексты).
- Форма состояния меняется только вместе с `SAVE_VERSION` (`session/storage.ts`, сейчас 7), списком действий на сервере и документацией.

## Сессия и экран

`GameSession` (`session/types.ts`) скрывает, как живёт игра:

- `store`: состояние игры (`getState`, `dispatch`, `subscribe`);
- `meta`: связь, игроки, ведущий, рекорд;
- `send(action)`: в одиночной игре применяется сразу, в совместной уходит на сервер и применяется, когда сервер разошлёт его всем;
- `tick(ms)`, `canTick()`, `save()`, `start()`.

`createSoloSession` автосохраняет раз в 2 секунды и пишет рекорд; `createOnlineSession` собирает игру из seed и уже случившихся действий и слушает поток сервера.

Экран читает состояние **кусочками**: `useGame(selector, isEqual)` перерисовывает компонент, только если выбранный кусок изменился. Благодаря этому 10 тиков в секунду перерисовывают только часы (`TopBar` → `GameClock`), а проценты стройки обновляет сам маленький компонент `LiveProgress`/`LivePercent`. `GameScreen` — только раскладка. Звуки подписаны на хранилище (`useSoundEffects`), а не на React-состояние.

Состояние интерфейса (выбранный модуль, режим размещения, правила) живёт в `features/game/GameUiProvider.tsx`, а не в игре.

## Тексты

`t(key: MessageKey)`: ключ проверяет компилятор. Ключи, которые собираются из id в данных (`task.${id}`, `ev.${id}.title`), идут через `tDynamic`; полноту переводов для них проверяет тесты в `tests/engine/`. Склонение «день/дня/дней» через `Intl.PluralRules`.

## Проверки

| Команда | Что проверяет |
|---|---|
| `npm run lint` | oxlint: хуки, экспорты компонентов, циклы импортов, `any` |
| `npm run typecheck` | `tsc -b` |
| `npm run architecture` | границы слоёв |
| `npm run check` | Vitest: баланс, механики, язык, сохранения и данные NASA (`tests/engine/`), комната совместной игры (`tests/online/`), хранилища и сессии (`tests/session/`), границы слоёв |
| `npm run golden` | «золотой прогон»: 60 игр, состояние без журнала совпадает со снимком `docs/baseline/` |
| `npm run build` | типы и сборка; CI ещё проверяет, что нет предупреждений о неразрешённых путях |
| `npm run e2e` | Playwright: запуск игры, совместные комнаты, роли, восстановление связи, итоги и язык |

«Золотой прогон» — страховка рефакторинга: поведение игры менять нельзя, пока снимок не обновлён осознанно.

## Как добавлять

- **Новое действие:** тип в `src/types.ts`, ветка в `engine/reduce.ts`, `ACTION_TYPES` в `shared/protocol.ts`, `SAVE_VERSION`, этот документ и проверка.
- **Новый модуль:** запись в `content/modules.json`, картинка в `features/game/map/art.tsx`, высота в `art-size.ts`, тексты `module.<type>.*` в трёх словарях.
- **Новый экран:** папка в `features/`, подписка на нужный кусок через `useGame`, без обращения к `engine/` внутренним путём.
