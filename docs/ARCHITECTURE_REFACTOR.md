# Рефакторинг архитектуры: цель, правила слоёв, шаги

Статус: **на утверждении** (@Regie). Автор плана: Claude. Дата: 2026-11-14.

Цель: сделать архитектуру **цельной, чёткой и стандартной**, не меняя поведение игры. Игрок не должен заметить разницы, кроме того, что станет быстрее и плавнее.

## 1. Диагноз (факты, проверено по коду)

| Проблема | Факт | Чем плохо |
|---|---|---|
| Ядро зависит от интерфейса | 6 файлов `src/engine/*` импортируют `i18n`, 37 вызовов `t()`. Журнал игры хранит уже переведённые строки | Состояние зависит от языка клиента, сохранение «знает» язык, ядро нельзя запустить без словарей, в совместной игре у игроков разный `state.log` |
| Монолит `Game` | В `App.tsx` 523 строки, из них `Game` 366, 38 хуков. Там же: сессия (соло и онлайн), автосохранение, звук, часы, тосты, баннеры, окна, рендер | Нельзя понять и проверить по частям, любая правка задевает всё |
| Лишние перерисовки | Часы шлют `tick` 10 раз в секунду, и весь `Game` перерисовывается 10 раз в секунду | Мешает плавной анимации 60 кадров, будет мешать косметике |
| Плоская структура `ui/` | 22 файла в одной папке, один глобальный `App.css` на 352 строки | Непонятно, что чему принадлежит, стили связаны неявно |
| Крупные файлы | `LunarMap.tsx` 555, `audio.ts` 785, `engine.ts` 362, `checks.ts` 456 | Много обязанностей в одном файле |
| Нестандартные тесты | Свой раннер `scripts/run-checks.mjs` и 456 строк в `checks.ts`, лежащих рядом с кодом ядра | Нет Vitest, нет отчёта, тесты попадают в `src/` |
| Протокол клиент-сервер «на честном слове» | Список действий дублируется в `server/index.mjs` и `types.ts`, сверяется регулярным выражением. Сервер на JS без типов | Хрупко, уже ломалось (исследование не работало онлайн) |
| Слабые правила качества | В `oxlint` два правила, 9 предупреждений, нет форматтера, нет `.editorconfig`, нет `engines`, нет `ErrorBoundary`, глубокие `../../` импорты | Стиль и границы слоёв ничем не защищены |
| Строковые ключи i18n | `t("...")` с любой строкой, часть ключей собирается на лету | Опечатка в ключе видна только в игре |

## 2. Целевая структура

```
shared/                  Протокол, общий для клиента и сервера (TS, без зависимостей)
  protocol.ts            ACTION_TYPES, ROLES, ROOM_NAME, типы сообщений
server/                  Сервер совместной игры (TS, Node 22 без сборки), использует shared/
src/
  app/                   Корень: App.tsx, машина экранов (меню → пролог → правила → игра)
  engine/                ЧИСТОЕ ЯДРО: без React, DOM, i18n и localStorage
    index.ts             Публичный API ядра (всё остальное внутреннее)
    reduce.ts            Корневой reducer: только маршрутизация действий
    state.ts, random.ts  Начальное состояние, seed
    actions/             build, repair, research, event, tick
    systems/             economy, crew, tasks, illness, time
    selectors.ts         capacityOf, dailyDelta, hasFreeCrew ...
    log.ts               Структурные записи журнала {day, key, params}
  content/               Данные игры: modules.json, events.json, map.ts, nasa/, facts, sources
  i18n/                  Словари, типизированные ключи, форматирование (Intl)
  session/               Как живёт игра: store (useSyncExternalStore), соло и онлайн, автосохранение, storage
  features/              Экранные функции, у каждой свои компоненты и CSS
    hud/ build/ crew/ tasks/ events/ results/ sources/ menu/ prologue/ map/
  ui/                    Общие примитивы: Modal, Button, Collapse, icons
  audio/                 Звук (разбить на synth, music, sfx)
  styles/                tokens.css, base.css, motion.css
tests/                   Vitest: engine/, session/, content/, i18n/
e2e/                     Playwright: дымовой проход и замер кадров (делает Codex)
```

Название `engine` оставляем: оно уже везде в документации и в голове у команды, меньше конфликтов при слиянии.

## 3. Правила слоёв (направление зависимостей)

```
content  ←  engine  ←  session  ←  features  ←  app
shared   ←  server           i18n ← features, session
```

1. `engine` импортирует только `content` и себя. **Не импортирует** React, DOM, `i18n`, `session`, `features`.
2. `content` не импортирует ничего, кроме типов.
3. `features` не импортируют друг друга напрямую, общее выносится в `ui/` или `session/`.
4. `session` знает про `engine` и сеть, но не про React-компоненты (кроме хуков).
5. Только `app/` собирает всё вместе.
6. `server` и клиент делят `shared/protocol.ts`, а не копируют списки.

Правила проверяет скрипт `scripts/check-architecture.mjs` (граф импортов), он входит в `npm run check` и в CI. Нарушение роняет проверку.

## 4. Шаги (каждый отдельный коммит, каждый зелёный)

| № | Шаг | Что делаем | Критерий готовности |
|---|---|---|---|
| A0 | Базовая линия | Ветка `regie-night` от `main`. «Золотой прогон»: 20 seed × 3 стратегии, итоговое состояние без `log` сохраняется в снимок. Замер кадров | Снимок и цифры сохранены в `docs/baseline/` |
| A1 | Чистое ядро | Журнал становится `{day, key, params}`. Ядро не импортирует `i18n`. `describeFlare` и форматирование журнала переезжают в UI. `SAVE_VERSION`+1, старые сохранения мигрируют (журнал очищается) | «Золотой прогон» совпадает с A0 (без `log`), `engine/` не импортирует `i18n` |
| A2 | Разбор ядра | `engine.ts` на `reduce`, `actions/`, `systems/`, `selectors`, публичный `index.ts` | Все проверки зелёные, снимок совпадает |
| A3 | Слой сессии | Хранилище на `useSyncExternalStore` с селекторами. `session/solo` (автосохранение, рекорды), `session/online` (клиент сети). Хуки `useGame`, `useAutosave`, `useOnlineSession`, `useSoundEffects` | `Game` меньше 120 строк, часы перерисовывают только себя |
| A4 | Экраны по функциям | `Game` делится на `features/*`, `EventModal`, `GameHud`. Стили рядом с компонентами, `App.css` делится на `base/layout`. Алиас `@/` вместо `../../` | В `ui/` только общие примитивы, нет глубоких относительных импортов |
| A5 | Типизированный i18n | Тип `MessageKey` из словаря, `t(key: MessageKey)`. Динамические ключи через функции-помощники. `Intl.PluralRules` вместо ручных склонений | Опечатка в ключе не компилируется |
| A6 | Данные | `content/`: карта, факты, источники в одном месте, единая схема | Нет данных, лежащих в `src/` вне `content/` |
| A7 | Стандарты | Расширить `oxlint` (корректность, границы импортов, хуки как ошибки), убрать 9 предупреждений, `.editorconfig`, `.nvmrc`, `engines`, скрипт границ слоёв. CI: lint, типы, тесты, сборка | CI роняет нарушения |
| A8 | Надёжность | `ErrorBoundary`, безопасная обёртка `localStorage`, понятные сообщения при потере соединения | Ошибка в компоненте не белит экран |
| A9 | Документы | `docs/ARCHITECTURE.md` с схемой и правилами, обновить `PROJECT_DOCUMENTATION.md` и `LLMS.txt` | Документы совпадают с кодом |

**Prettier-форматирование всего репозитория не делаем ночью:** это огромный diff, который сломает все чужие ветки. Предлагаем сделать его отдельным коммитом после слияния всех веток, по твоему «да».

## 5. Что делает Codex параллельно (чтобы не пересекаться)

См. `docs/CODEX_TASK.md`: порт проверок на **Vitest**, **общий протокол и сервер на TS**, **Playwright** (дымовой проход и замер кадров). Это папки `tests/`, `shared/`, `server/`, `e2e/`, они не пересекаются с моими `src/engine`, `src/session`, `src/features`.

## 6. Ворота качества

После каждого шага: `npx tsc -b`, `npm run check`, `npm run build`, «золотой прогон» (состояние без `log` совпадает с A0), для интерфейса ещё скриншот. Не прошло: откат шага и запись в отчёт.

## 7. Риски

- **Конфликты с коллегами.** Файлы переезжают, а Fixby-V и w1lderrr продолжают править `src/`. Git распознаёт перенос файлов, но правки внутри переехавших файлов дадут конфликты. Решение: перед ночью сообщить команде «src/engine, src/App.tsx и структуру src/ui не трогать до утра», а утром слить вместе.
- **Рассинхрон совместной игры.** Смена формата журнала меняет состояние: `SAVE_VERSION` и защита от старых клиентов.
- **Объём.** За ночь могут не уложиться все 10 шагов. Они упорядочены по ценности, каждый можно остановить, оставив зелёную ветку.
- **Поведение не меняем.** Любое расхождение «золотого прогона» считается ошибкой рефакторинга, а не особенностью.
