# Задание для GitHub Copilot (coding agent)

Репозиторий: игра «Лунная база» (React 19 + TypeScript + Vite, чистый движок, Node-сервер совместной игры). Прочитай сначала `README.md`, `docs/ARCHITECTURE.md` и `LLMS.txt`. Это задание **только про тесты**: нужно покрыть то, что сейчас не покрыто, и ничего не ломать.

## Правила (жёсткие)

1. Работай в новой ветке **`copilot/tests`** от свежего `main`. **Не пушь в `main`.** Открой PR в `main` и не сливай его сам.
2. Меняй только `tests/`, `e2e/` и (если без этого никак) `package.json` (скрипты) и `docs/`. **Файлы в `src/`, `server/`, `shared/` не правь.** Если нашёл баг в них, не чини, а опиши в PR («Найденные проблемы»).
3. Движок (`src/engine/`) детерминирован: в тестах не используй `Math.random` и `Date.now` для сценариев игры, берись `initialState(seed)`.
4. Не придумывай данные NASA, не меняй баланс, цены, тексты и правила игры.
5. Перед каждым коммитом всё должно быть зелёным: `npm run lint`, `npm run typecheck`, `npm run check`, `npm run golden`, `npm run build`. `npm run e2e` для задач 2–3 тоже.
6. Коммиты маленькие, по одной задаче. Сообщения на английском.

## Задача 1. Тесты слоя сессии (Vitest, `tests/session/`)

Слой `src/session/`: `store.ts` (`createStore`, `createValueStore`, `shallowEqual`), `solo.ts` (`createSoloSession`), `online.ts` (`createOnlineSession`), `storage.ts`. Сейчас у него нет прямых тестов.

Покрыть:
- `createStore`: `dispatch` меняет состояние, подписчики вызываются; **не вызываются, если редюсер вернул ту же ссылку**; отписка работает.
- `createValueStore`: `set` значением и функцией, не будит подписчиков при равном значении.
- `shallowEqual`: примитивы, объекты с теми же значениями, массивы, `null`, разное число ключей.
- `createSoloSession`: `send({type:"tick", ms})` двигает игру, `start()` возвращает функцию отмены и безопасен при повторном вызове (StrictMode), автосохранение пишет в `localStorage` не чаще раза в 2 секунды (используй `vi.useFakeTimers` и подставной `localStorage`, как в `tests/engine/extras.test.ts`), по окончании миссии рекорд записывается **один раз**, `save()` сохраняет только пока `status === "playing"`.
- `createOnlineSession`: на заглушке `Session` (поля из `src/net/online.ts`): состояние собирается из `seed` и уже случившихся `actions`; `tick` копится и уходит на сервер пачками не меньше 500 мс; `canTick()` верно для ведущего и для остальных.

Подставляй `localStorage` и `EventSource` через `vi.stubGlobal`. Пример подстановки есть в `tests/engine/extras.test.ts`.

## Задача 2. e2e: совместная игра глубже (`e2e/online.spec.ts`, `e2e/online-roles.spec.ts`)

Уже есть `e2e/online.spec.ts` (двое входят в комнату и видят общее время). Добавить:
- У двух игроков **разные роли** (сервер раздаёт случайно; прочитай роль из плашки «Сервер X · ты: …»), модуль, закреплённый за ролью другого игрока, у первого заблокирован (`online.lockedBy`), а свой строится и появляется **у обоих** игроков.
- Потеря связи: останови сервер на время (через `page.route` с `abort` для `/api/**` или закрытием соединения), покажи баннер «Связь с сервером потеряна», верни связь и проверь, что игра продолжилась без повторного применения действий (счётчик действий не удваивается).
- Третий игрок в той же комнате: получает четвёртую роль, пятый получает отказ с понятным сообщением.

Подсказки: селекторы бери по ролям и видимому тексту на русском (язык ставится в `playwright.config.ts` через `storageState`), тексты в `src/i18n/ru.ts`. Клик по клетке карты делай как в `e2e/smoke.spec.ts` (ищи `.tile-ok`, не фиксируй координаты).

## Задача 3. e2e: итоги и язык (`e2e/results.spec.ts`)

- Дойди до конца миссии быстро: нужно ускорить игру. **Не меняй `src/`**: используй `page.clock.install()` / `page.clock.fastForward()` из Playwright, чтобы прокрутить время (день = 90 с, миссия 20 дней), и проверь, что показывается ролик конца, затем итоговый экран («Итоги» с оценкой, блоками «Что помогло» и «Что помешало», фактами NASA).
- Проверь три языка (меню → «Мова/Language/Язык»): заголовок меню, кнопка «Новая игра» и экран «Данные NASA» (там должен быть источник «RadLab» со статусом «в игре» и «ECLSS») читаются на ru, uk и en без сырых ключей вида `app.xxx`.
