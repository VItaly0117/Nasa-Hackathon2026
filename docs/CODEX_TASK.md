# Задание для Codex: инфраструктура проверок и протокола

Это самодостаточное задание. Его можно вставить в Codex целиком. Работа идёт **параллельно** с Claude, который в это время переделывает `src/` (ядро, сессии, экраны, стили, звук). Поэтому ты **не трогаешь `src/`** (см. правила). Потом ветки сливаются вместе.

## Контекст

Moonbase: игра про лунную базу на 20 дней (React 19 + TypeScript + Vite, чистое ядро `src/engine/`, сервер совместной игры `server/index.mjs` на чистом Node без библиотек). Прочитай сначала `PROJECT_DOCUMENTATION.md` и `docs/ARCHITECTURE_REFACTOR.md`. Главный инвариант: **ядро детерминировано** (никакого `Math.random` и `Date.now` внутри `src/engine/`). Совместная игра работает так: сервер хранит seed комнаты и общий журнал действий, а каждый клиент проигрывает их через `reduce`.

Сейчас проверки живут в `src/engine/checks.ts` (456 строк, около 66 проверок) и запускаются своим раннером `scripts/run-checks.mjs` через Vite SSR. Протокол сервера проверяет `scripts/run-online-checks.mjs`, сверяя списки действий регулярным выражением.

## Правила

1. Ветка `codex/infra` от свежего `origin/main`. **Не пушить в `main`**, не открывать и не сливать PR, не делать `push --force`.
2. **Не менять ничего в `src/`.** Если тебе нужен селектор для e2e (`data-testid`) или правка в коде игры, **не делай**, а запиши в `docs/CODEX_REPORT.md` в раздел «Нужно от Claude».
3. Каждая задача отдельным коммитом. После каждого коммита `npm run check` и `npm run build` должны быть зелёными (пока старый раннер не заменён, он остаётся рабочим).
4. Не добавляй зависимости без нужды. Разрешены: `vitest`, `@playwright/test`. Версии фиксируй точными.
5. Не придумывай данные и не меняй правила игры. Тесты проверяют то, что есть.
6. Если лимиты заканчиваются: закончи текущий шаг до зелёного состояния, закоммить, обнови `docs/CODEX_REPORT.md` («что сделано», «что осталось», «как продолжить»). Лучше не доделать, чем оставить красную ветку.

## Порядок задач (от самой ценной)

### T1. Порт проверок на Vitest (страховочная сетка для рефакторинга)
- Добавить `vitest`, конфиг `vitest.config.ts`, папку `tests/`.
- Перенести **каждую** проверку из `src/engine/checks.ts` в тесты, разложив по темам: `tests/engine/economy.test.ts`, `build-and-crew.test.ts`, `tasks.test.ts`, `illness.test.ts`, `debrief.test.ts`, `research.test.ts`, `content.test.ts` (данные, тексты, подсказки совпадают с ценами), `determinism.test.ts`.
- **Составь таблицу соответствия** в `docs/CODEX_REPORT.md`: старая проверка, новый тест. Ни одна проверка не должна пропасть.
- Все импорты движка делай через один файл `tests/helpers/engine.ts` (он реэкспортирует нужное из `src/engine/*`). Claude перенесёт файлы ядра, и ему придётся поправить только этот файл.
- Добавить тесты, которых не хватает: `loadGame`/`saveGame`/рекорды с подставным `localStorage` (миграция версии, битые данные, порядок и лимит 10 рекордов), `missionFact` и `buildReport` на нескольких seed.
- `npm run check` = Vitest + `scripts/run-online-checks.mjs`. Старый раннер удалить **только после** полного соответствия по таблице.

### T2. Общий протокол и сервер на TypeScript
- Создать `shared/protocol.ts`: `ACTION_TYPES`, `ROLES`, правило имени комнаты, типы сообщений сервера. Без зависимостей.
- Перевести `server/index.mjs` в `server/index.ts`. Node 22.21 запускает TS без сборки (стирание типов), в `tsconfig` уже включено `erasableSyntaxOnly`. Импорты с расширением `.ts`.
- Сервер и клиентский `src/net/online.ts` должны брать списки из `shared/protocol.ts`. **Но `src/` не трогай:** вместо правки `online.ts` положи в отчёт точный патч, а в `tests/` проверь, что серверный список равен типу `Action` из `src/types.ts`.
- Заменить регулярное выражение в `run-online-checks` настоящим тестом Vitest: сервер поднимается, проверяются роли, права ведущего, каждое действие движка пропускается, неизвестное отклоняется.
- `npm run server` продолжает работать.

### T3. Playwright: дымовой проход и замер кадров
- `e2e/smoke.spec.ts`: меню → «Новая игра» → пропустить пролог → «Начать миссию» → поставить модуль → дождаться задания и таймера. Без выдуманных селекторов: используй роли и видимый текст, на трёх языках только русский.
- `e2e/perf.spec.ts` и `npm run perf`: 60 секунд игры, счётчик кадров через `requestAnimationFrame`, `PerformanceObserver` для долгих задач. Выводит: средний FPS, процент кадров дольше 33 мс, число задач дольше 50 мс. **Порог:** средний FPS не ниже 55, кадров дольше 33 мс не больше 3%, долгих задач ноль после загрузки.
- Использовать установленный Chrome (`channel: "chrome"`), не скачивать браузеры, если это возможно.
- `npm run e2e` отдельный скрипт, в `check` не входит (он медленный).

### T4. CI
- В `.github/workflows/ci.yml`: Vitest в шаг проверок, отдельный необязательный шаг e2e. Не менять шаги сборки и деплоя `deploy.yml`.

## Что сдать

- Коммиты T1–T4 в `codex/infra`.
- `docs/CODEX_REPORT.md`: таблица соответствия, что сделано, что не получилось и почему, раздел «Нужно от Claude» (патчи для `src/`, нужные `data-testid`), как запустить всё локально.
- Ничего не сливать в `main`: сольём вместе утром.
